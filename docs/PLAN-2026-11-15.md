## 3. AI tool procedure — RESOLVED

**Date resolved:** 2026-11-08
**Resolved by:** Project supervisor (Bibi Leung)

### 3.1 What was resolved

Two previously open questions are now answered:

1. **Is there an established procedure for using AI tools in the capstone project?**
   Yes. Under the reimbursement scheme framework (EDUHK-REIMBURSEMENT-2026), the project supervisor's pre-approval constitutes the **complete** procedural requirement for AI tool use in the capstone project. No separate LTTC application or external-API approval process is required beyond this pre-approval.

2. **Does EdUHK provide an approved LLM service?**
   Yes. LTTC provides LLM Studio (front-end) backed by a MaaS (Model-as-a-Service) platform. Students access it primarily through:
   - Workshops explicitly aimed at students
   - Credit-bearing courses that incorporate the tool

   It is **not** a public, no-registration chat interface. The access model is structured.

### 3.2 What this means for the project

- The project may proceed with AI integration under the supervisor's pre-approval.
- If the model uses LTTC's LLM Studio, the access model (workshops/courses) must be accounted for in the integration plan.
- If the model uses an external API, the reimbursement scheme covers up to HK$5,000, but only if the tool is not available from LTTC.
- The template-based baseline remains the zero-hallucination control condition regardless of which model path is chosen.

### 3.3 Funding decision

The supervisor's note on the reimbursement guideline — "approved only if they are not available from LTTC or the course-offering department" — also answers the account-funding question. LTTC is checked first. If LTTC's LLM Studio is sufficient for the project's needs, no reimbursement is needed. If an external API is needed (e.g., for a model not on the MaaS platform), the reimbursement applies, with pre-approval by 30 Nov 2026.

**Decision needed by 30 Nov 2026:** Whether to use LTTC's LLM Studio or request reimbursement for an external API. This decision should be made in consultation with the supervisor.

## 4. Corpus design — supervisor confirmation

**Date confirmed:** 2026-11-08
**Confirmed by:** Project supervisor (Bibi Leung)

The supervisor confirmed that corpus exemplars can be:
- **Self-authored / synthetic** — written by the student or generated by a model and edited
- **Real cases** — actual student emails collected with consent, or public model emails from university writing centres

Both are acceptable. This resolves the concern about the corpus being entirely synthetic: the supervisor has explicitly endorsed it.

### 4.1 Target

- 40 human-verified exemplars (annotated with Swales move analysis + Biesenbach-Lucas e-politeness features)
- 60 synthetic input scenarios (for testing the Gatekeeper and lint, not as gold-standard exemplars)
- 10–15 public model emails from university writing centres (preferred provenance class)

### 4.2 Provenance separation

Synthetic data may serve as **input scenarios** (what the student types into the tool) but should be distinguished from **reference exemplars** (what the tool compares against). The circular-argument risk — a model trained on its own outputs — is mitigated by this separation.
